# SakuttoSeat v2.1.0 実装計画

**UI/UX 磨き込み（HIG）**  
対象バージョン: **2.1.0**  
位置づけ: 発表・書き出し・会場拡張の機能実装は完了済み。リリース前に HIG 観点の修正を同梱する。  
前提: `docs/v2.1_ExportAndPresentation.md` / `docs/v2.1_LimitsAndVenueExpansion.md` の機能仕様は変えない。広告・上限・VIPER の層分担も変えない。

レビュー原本: チャット横 Canvas「v2.1.0 UI/UX レビュー」

## 0. 判断の軸

v2.1 の約束は「決めて・見せて・渡す」。今回直すのは機能不足ではなく、**入口が伝わらない / 小画面で欠ける / 壁に出したとき読めない / 操作の約束がズレている**こと。

やってよいこと:

- Copy の分岐、シート detent、ツールバーラベル、発表キャンバスの gestural / タイポ、ヒット領域、VoiceOver 名
- 参加者リスト CTA が未確定入力を握りつぶさないこと
- 座席表の「お気に入り」ラベルをテンプレートに揃えること（一覧の中身は変えない）

やってはいけないこと:

- 新画面・新 VIPER モジュールを増やす
- 発表を独立 Presenter / Interactor にする
- リワードの要否、セッション解放フラグ、CSV / PNG の中身、バナーのマウント規約を変える
- Snapshot / `ImageExportRenderer` の固定 pt を Dynamic Type に乗せ替える（書き出し画像が端末の文字サイズで変わる）
- 座席表下段に5つ目のボタンを足す

## 3. Phase 1 — 共有シート（S1 / S2 / S3）

### 3.1 現状

- `ShareSelectionView` が `.presentationDetents([.medium])` のみ。4行×本文+2行字幕+14pt パディングは iPhone SE の medium（約 333pt）に収まらない。
- `ShareCopy.subtitle` / `confirmMessage` の `.image` が「座席表画像」固定。番号札から開いても座席表の話になる。
- 確認アラートの主ボタンが `OK`。会場拡張は「動画を見て追加する」で、動詞になっていない。

### 3.2 仕様

**S1 シート高さ**

- detent は **`.medium` と `.large`**。既定は medium のまま。
- `.presentationContentInteraction(.scrolls)` を付け、medium で4行が切れてもスクロールできる。
- ドラッグインジケータは維持。キャンセルは最下段のまま。
- 行の内側パディングは 14 → **10–12pt**。字幕は可能なら1行（`lineLimit(2)` は保険で残してよい）。
- 行末の `chevron.right` は **削除** する。ここはプッシュ遷移ではなくアクション選択。再生バッジは未解放時のみ残す。
- 行の `buttonStyle(.plain)` は維持してよいが、押下時に opacity が落ちること（ハイライト）は保つ。

**S2 対象別コピー**

`ShareCopy` の字幕・確認文は `ShareSubject`（または `.seatingChart` / `.numberedList` の小さい enum）を受け取る。

| kind | 未解放・座席表 | 未解放・番号札 |
|---|---|---|
| text | 無料ですぐに共有できます（変更なし） | 同左 |
| image | 動画を見てきれいな座席表画像を保存・送信 | 動画を見てきれいな番号札画像を保存・送信 |
| highResImage | 余白カット・印刷や投影向き（対象中立・変更なし） | 同左 |
| csv | Excel・名簿ソフトで二次利用（変更なし） | 同左 |

解放済みの有料3種は現行どおり「この起動中はすぐに書き出せます」。

確認本文:

| kind | 座席表 | 番号札 |
|---|---|---|
| image | 動画を見て、きれいな座席表画像を保存・送信しますか？ | 動画を見て、きれいな番号札画像を保存・送信しますか？ |
| highResImage | 動画を見て、余白を切った高画質画像を保存・送信しますか？（変更なし） | 同左 |
| csv | 動画を見て、Excelで開けるCSVを書き出しますか？（変更なし） | 同左 |

`ShareSelectionView` と `ShareFlowModifier` は `presenter.subject` を渡す。subject が nil のときは座席表側の文言にフォールバック（シート表示中は `didTapShare` 済みなので通常は非 nil）。

**S3 確認ボタン**

有料確認の主ボタンは **「動画を見て書き出す」**（`ShareCopy.confirmPrimary`）。副ボタンは **「キャンセル」** のまま。

会場拡張の「あとで」には寄せない。共有はフローを捨てる操作、会場拡張は入力の途中だから。失敗系（未準備 / 書き出し失敗）の OK は変えない。

## 4. Phase 2 — 発表モード（P1 / P2 / P3）

### 4.1 現状

- ナビ左が `rectangle.inset.filled` のみ。SF Symbol に「発表」の意味がなく、戻るの隣で埋もれる。
- ヒントは「画面をタップして終了」。実装のタップは閉じるピルの再表示。下スワイプは `startLocation.y < 56` かつ 80pt。
- 発表の席名 16pt。番号札カードは人数・横幅に関係なく常に2列。高画質スナップショットは既に人数で列数を変えている。

### 4.2 仕様

**P1 入口**

座席表・番号札の leading ツールバー:

```swift
Label(PresentationCopy.presentToolbarTitle, systemImage: "rectangle.inset.filled")
    .labelStyle(.titleAndIcon)
```

- 可視化ラベルは **「発表」**（`presentToolbarTitle`。a11y ラベルと同じでよい）。
- アイコンは現行のままでよい。ラベルが発見性を担う。
- 無効時 Hint:
  - 座席表: 「テーブルがないと発表できません」
  - 番号札: 「参加者がいないと発表できません」
- 有効時 Hint は現行（全画面で表示します）を維持。
- 下段4ボタンには足さない（既存方針）。

狭い幅で「戻る + 発表」が折り返す場合は `.labelStyle(.titleOnly)` に落とすより、タイトル「発表」を優先する（アイコンより言葉）。

**P2 終了**

約束を実装に合わせる。投影中に誤って閉じにくいことも残す。

| 操作 | 仕様 |
|---|---|
| 初回2秒のヒント | **「画面をタップすると閉じるボタンが出ます」**（`tapToDismissHint` を置換） |
| 画面タップ | 現行どおり閉じるピルを 3 秒出す。タップでは直接閉じない |
| 閉じるピル | 押すと終了。ヒット領域は `minTapTarget` |
| 下スワイプ | **開始位置の y < 56 制限を外す**。`translation.height > 80` かつ横移動より縦が明らかに大きいとき閉じる（誤スクロールで閉じない） |
| VoiceOver | 現行の `accessibilityAction`「発表を終了」と、閉じるコントロールを残す（opacity 0 でも `accessibilityHidden(false)`） |

座席表の発表中スクロールとスワイプ閉じが競合したら、縦スクロールが明らかに内容を動かしているときは閉じない。判定は「translation.height > 80 かつ abs(width) < height/2」で足りる。ScrollView の `simultaneousGesture` は維持。

**P3 可読性（発表キャンバスだけ。画面の通常座席表は Phase 6）**

席（`SeatingChrome.presentation`）:

- 氏名は `.title3.weight(.semibold)`（16pt 固定をやめる）
- 人アイコンは氏名より小さく（`.title2` 程度）。空席も同様
- `minimumScaleFactor` は 0.7 のまま
- ロック印は出さない（現行）

番号札発表グリッド:

- 列数は幅と人数で決める。ロジックは **純関数** にしてテストする（View に直書きしない）

```swift
enum PresentationNumberedLayout {
    /// 1人は1列。幅が足りれば 2–4 列。
    static func columnCount(rowCount: Int, containerWidth: CGFloat) -> Int
}
```

目安（実装者が微調整してよい。テストは境界を固定する）:

- `rowCount <= 1` → 1
- 幅 < 500 → 2（人数1のときは1）
- 幅 500..<700 → min(3, rowCount)
- 幅 >= 700 → min(4, rowCount)

番号は `.largeTitle`（44pt 固定をやめる）。氏名は `.title2.weight(.semibold)` のまま拡大してよい。

40人が縦 iPhone で 1–2 画面スクロール、横向き / iPad で列が増えることを目視確認する。

書き出し Snapshot の列数ロジックには **繋げない**（画像レイアウトを変えない）。

## 5. Phase 3 — 参加者リスト CTA とヒット領域（A1 / A3）

### 5.1 A1 未確定名

現状 `seatingDisabled = !canStartSeating || !newName.isEmpty` のため、名前を打ちかけただけで両方の CTA が死ぬ。理由も出ない。入力1件目を確定せず「座席表で決める」を押す経路も封じている。

**仕様**

CTA の enabled:

- 参加者が1人以上いる、**または** 入力欄の trim 後が空でない
- ハード上限で入力欄が disabled のときは、参加者ゼロにはならないので `canStartSeating` 側で生きる

タップ時（座席表 / 番号札共通）:

1. 入力を trim する
2. 空 → 既存どおり `didTapSeatingChart()` / `didTapSimpleShuffle()`（参加者がいなければ押せていない）
3. 非空 → 既存の `didTapAdd(name:)` と同じ `CapacityDecision` を通す
   - `.allowed` → 追加して入力を空にし、遷移する
   - `.requiresUnlock` → 人数解放アラート。**遷移しない**（視聴成功後の既存再開で名前は入る。遷移はユーザーがもう一度 CTA を押す）
   - `.blockedHardLimit` → ハード上限アラート。**遷移しない**

Presenter に `didTapSeatingChart(pendingName:)` を足さず、View が「先に `didTapAdd`、true なら遷移」でもよい。Unlock で `didTapAdd` が false を返す現行契約を使う方が差分は小さい。

キーボードは遷移前に閉じる（現行の `isTextFieldFocused = false`）。

`submitLabel` は連続入力向けに **`.done` → `.join`**（または `.next`）へ変更する。追加成功後にフォーカスを戻す現行は維持。

### 5.2 A3 ヒット領域

HIG 44×44pt。見た目のアイコンを大きくしなくてよい。`frame(minWidth:minHeight:)` と `contentShape(Rectangle())` で取る。

| 対象 | ファイル | 内容 |
|---|---|---|
| 参加者の＋ | `AttendeeListView` | ボタンに `minTapTarget`。再生バッジはヒットを狭めない |
| 発表の閉じる | `PresentationCanvas.closeControl` | カプセル全体で `minTapTarget` 以上 |
| テーブル追加カード | 既存 minHeight 120 で充足。変更不要 |
| 下段 ActionButtons | 高さ 50 で充足。変更不要 |

カスタム `ButtonStyle`（`SakuttoPrimaryButtonStyle`）は今回、disabled 見た目の読み取りまで広げない。A1 で CTA を殺す理由が減る。

### 5.3 触るファイル

- `SakuttoSeat/Modules/AttendeeList/AttendeeListView.swift`
- 必要なら `AttendeeListPresenter`（pending 付き API にする場合だけ）
- `SakuttoSeat/Core/DesignSystem/AppSpacing.swift`
- `SakuttoSeat/Modules/Presentation/PresentationCanvas.swift`（閉じるの frame）
- `SakuttoSeatTests/AttendeeListPresenterTests.swift`（API を Presneter に足した場合）

### 5.4 テスト

Presenter にロジックを寄せた場合:

- 参加者0 + pending「太郎」→ add 成功 + seatingChart ルート
- 無料枠ちょうど + pending → 解放アラート、ルートは nil のまま
- 120人 + pending → ハード上限、ルートは nil
- 参加者あり + pending 空 → そのまま遷移（追加しない）

View 内で `didTapAdd` を先呼びする場合、Presenter テストは現行 `didTapAdd` で足りる。そのときは目視チェックリストに「1件目を＋せず CTA で入れる」を書く。

## 7. Phase 5 — 用語とアフォーダンス（L1 / L3）

### 7.1 L1 座席表の「お気に入り」

参加者リストの「お気に入り」は **グループ名簿**。座席表下段の「お気に入り」は **レイアウトテンプレート** を開き、シートタイトルは「テンプレート読込」。同じ言葉が別物を指している。

**仕様（座席表側だけ変える）**

| 要素 | 変更後 |
|---|---|
| 下段ボタン1のタイトル | **テンプレート** |
| アイコン | `square.grid.2x2`（星は名簿側に残す） |
| 色 | 現行オレンジのままでよい |
| シートタイトル | 「テンプレート読込」のまま |
| 保存ボタン | 「保存」のまま（テンプレート保存） |
| 参加者リストの「お気に入り」 | **変えない** |

`SeatingChartView` のボタンタイトルを `SeatingTemplateCopy` か新 `SeatingChartCopy` から取る。テスト `SeatingTemplateTests` の navigationTitle 断言は維持。

### 7.2 L3 隠れた操作を見つける

現状: 卓カード全体タップで編集、席タップでロック。見た目の手がかりがない。チュートリアルや初回ツールチップは出さない（「サクッと」を止める）。

**卓**

- インタラクティブ時のみ、卓名の右に小さな `pencil`（`.caption`、secondary）
- VoiceOver: 卓の Hint「ダブルタップでテーブルを編集します」。席は子として辿れること
- 発表 chrome では鉛筆も `onTapGesture` も出さない（現行どおり読み取り専用）

**席**

- 見た目の「ロックしてね」キャプションは席ごとに出さない（密度）
- 各席 Button に:
  - Label: 氏名（空席は「空席」）
  - Value: ロック中なら「ロック中」
  - Hint: 空席は Hint なし。着席中は「ダブルタップでロックします」/「ダブルタップでロックを解除します」
- 親 `SeatingTableView` の `.accessibilityLabel(accessibilitySummary)` が席の探索を潰しているなら、**親は grouping に留め、氏名リストを Label に載せすぎない**。Summary は「テーブルA、4人着席、定員4」のままでよい。`accessibilityElement(children: .contain)` を維持し、席が個別フォーカスできることを VoiceOver で確認する

`SeatView` に a11y を足してよい。ロック色の赤は今回変えない（意味の再設計になる）。

### 7.3 触るファイル

## 8. Phase 6 — Dynamic Type（L2）

### 8.1 範囲

**画面の文字**をテキストスタイルへ。**書き出し Snapshot は固定 pt のまま**（`SeatingChartSnapshotView` / `SimpleShuffleSnapshotView` / `ImageExportRenderer` は触らない）。

| 対象 | 現行 | 変更 |
|---|---|---|
| 通常席の氏名 | 11pt | `.caption.weight(.medium)` |
| 発表席の氏名 | 16pt | Phase 2 で `.title3` 済みなら追加変更なし |
| 卓名（通常 / 発表） | `.caption` / `.headline` | そのままでよい（スタイル済み） |
| 向きラベル | 10pt / 13pt | `.caption2` / `.footnote` |
| 番号札発表の番号 | 44pt | Phase 2 で `.largeTitle` 済みなら追加変更なし |
| EmptyState アイコン | 80pt / 50pt | `.largeTitle` か `@ScaledMetric`。装飾なので厳密でなくてよい |
| NumberedPersonRow | `.subheadline` / `.body` | 変更なし |
| ロック印 10pt、向きバッジ矢印 8pt | 装飾 | 変更なし |

Dynamic Type XXXL で発表40人が崩れるのは許容する。列数（P3）で横向きを楽にする。文字サイズ用の独自クランプは作らない。

Reduce Motion / 触覚フィードバックは本計画の対象外。

### 8.2 テスト

スナップショット画像のピクセルテストは既存のまま通ること。画面フォントの XCTest は必須にしない。目視: 設定 → 文字サイズを最大付近にして参加者リスト・座席表・発表がクリップしすぎない。

## 9. 受け入れ条件

機能仕様（発表中に広告が出ない、書き出し4択、会場拡張1本、など）は既存ドキュメントのまま。加えて:

**共有**

- SE 相当の高さで、4択とキャンセルに手が届く（medium でスクロール、または large）
- 番号札から開いた画像の字幕・確認文が「番号札」であり「座席表」ではない
- 確認の主ボタンが「動画を見て書き出す」
- テキスト無料・解放後スキップ・列数フラグ非共有は回帰で緑

**発表**

- ツールバーに「発表」の文字が見える
- 空／テーブルなしでは押せない。VoiceOver が理由を読む
- ヒントが「閉じるボタンが出ます」。タップ1回では終了しない。中央からの下スワイプで終了できる
- VoiceOver で「発表を終了」が辿れる
- 縦 iPhone の番号札が2列、広い幅で3–4列
- 発表の席名が通常より大きい。バナー・下段・追加・ロック印が出ない

**参加者リスト**

- 名前入力中でも CTA が押せる
- 未確定名は追加されてから遷移する。解放が必要ならアラートのみ
- ＋と発表の閉じるが 44pt 以上

**用語・a11y・DT**

- 座席表下段が「テンプレート」。参加者リストの「お気に入り」は名簿のまま
- ギアが「会場設定」。卓追加・方向キーに名前がある
- 卓に鉛筆。VoiceOver で席を個別にロックできる
- 画面の席名が Dynamic Type で動く。書き出し画像のサイズは文字サイズ設定に依存しない

## 10. 目視チェック（実機またはシミュレータ）

必須端末イメージ: **iPhone SE サイズ** と **標準 iPhone 縦 / 横**。iPad があれば番号札発表の4列を見る。

1. 共有4択を SE 相当で開き、切れない / スクロールできる
2. 番号札 → 共有 → 画像、文言が番号札
3. 座席表ナビに「発表」。戻ると参加者リストへ戻れる
4. 発表を開き、2秒ヒント、タップで閉じる、中央スワイプで閉じる、投影相当の距離で氏名が読める
5. 参加者0で名前だけ打って「座席表で決める」→ 1人入った状態で座席表
6. VoiceOver: 発表終了、無効な発表、会場設定、卓追加、席のロック
7. 文字サイズ最大で座席表の氏名が 11pt のままになっていない
8. 画像・CSV の書き出し1本（回帰。レイアウトが大きく変わっていないこと）

## 11. 実装者向けメモ

- 広告・上限・CSV BOM・高画質スケールは触らない。壊すと v2.1 の本機能レビューがやり直しになる
- `ShareCopy.subtitle` のシグネチャを変えると `ShareTests` が赤くなる。Phase 1 で先に直す
- 発表の `Label` 追加でナビが狭いときは、アイコンより「発表」の文字を残す
- Phase 5 の星アイコン廃止は、参加者リスト側の星と役割が被っていたための変更。保存（矢印）は触らない
- コミット分割例:
  1. `fix(share): 4択シートの欠けと番号札コピー`
  2. `fix(presentation): 発表のラベル・終了・可読性`
  3. `fix(attendee): 未確定名でも席決めできる`
  4. `fix(a11y): ツールバーとピッカーの名前`
  5. `fix(seating): テンプレート表記と編集アフォーダンス`
  6. `fix(typography): 画面テキストを Dynamic Type へ`

質問が必要になる判断は Phase 2 のスワイプ閾値と番号札列数の境界だけ。上の表で実装してよい。文言の微修正は Copy テストを更新してから変える。
